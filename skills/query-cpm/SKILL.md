# Query CPM

## 使用原则

当用户反馈某媒体 CPM 下降时，先明确对比对象与时间口径，再用 `query-mapping` 技能确定字段映射、数据集和筛选条件。不要自行臆造字段名。

如果用户没有给全信息，优先追问：

1. 反馈媒体与对标媒体：媒体名称、`uid`、`appid` 或 `posid`。
2. 下降时间范围与对比时间范围。
3. 是否限定广告场景、行业、产品、优化目标或广告位。

## 排查流程

1. 对比两家媒体的预算结构差异：
   - 按行业看消耗占比、CPM、CTR、CVR。
   - 按产品看消耗占比、CPM、CTR、CVR。
   - 标出反馈媒体相对缺失或占比下降的高 CPM 行业/产品。

2. 对比两家媒体的场景结构与各场景 CPM：
   - 按广告场景汇总消耗、曝光、点击、转化、CPM、CTR、CVR。
   - 区分是场景占比变化导致整体 CPM 下降，还是同场景 CPM 本身下降。
   - 优先关注消耗占比高、CPM 差异大、环比变化明显的场景。

3. 在同一广告场景下对比头部预算产品与优化目标：
   - 取同场景下消耗 Top 产品和优化目标组合。
   - 判断两家媒体的头部产品与优化目标是否相似。
   - 若相似，重点对比 `CPM`、`CTR`、`CVR`，定位是点击效率还是转化效率拖累。
   - 若不相似，优先解释为预算结构或流量适配差异，不直接归因到媒体质量。

4. 针对较差指标给建议：
   - `CTR` 降低：拆成曝光量和点击量看。若曝光量增加但点击量未同步增长，多数是开发者自行调整导致曝光变多、点击效率被稀释；建议安装开发者应用实际查看广告位展示情况，并与开发者确认是否调整了广告位、曝光策略或流量入口。
   - `CVR` 降低：先定位是整体降低，还是个别预算产品/优化目标降低；再看对应 `CPM` 是否因此有明显变化。若只有个别头部产品 CVR 变差，建议针对产品、优化目标、人群和落地页链路排查。
   - 预算结构较差：若反馈媒体缺少高 CPM 产品或高价值优化目标，建议补齐相近产品预算、争取高 CPM 场景，并调整人群以提升点击率和转化匹配度。

## 输出格式

输出时按这个顺序组织：

1. 结论摘要：说明 CPM 下降主要由预算结构、场景结构、同场景效率，或多个因素共同导致。
2. 关键证据：列出最能支撑结论的行业/产品/场景/优化目标差异。
3. 指标拆解：说明 CPM、CTR、CVR 分别如何变化，指出主拖累项。
4. 建议动作：给出面向运营、媒体沟通或开发者排查的具体建议。
5. 待补充信息：仅在口径缺失或无法确认归因时列出。

## 注意事项

- 字段映射、默认时间口径和数据集选择必须复用 `query-mapping` 技能。
- 对比媒体时保持同一时间范围、同一过滤条件和同一聚合粒度。
- 不把整体 CPM 下降直接等同于媒体变差；先排除预算结构和场景结构变化。
- 对小样本场景或产品谨慎下结论，优先看消耗占比高的部分。
