# 错误处理对照表

这是执行时的错题本。脚本报错先查这里，别自由发挥——这个 Skill 会写生产策略，
猜错一步就是拉错系数。

判断成功必须**同时**满足两个条件：进程退出码为 `0`，且 stdout 最后一行的
业务 JSON 里 `ok=true` / `code=0`。只看其中一个会漏判。机器可读的映射在
[error-policy.json](error-policy.json)。

## 退出码

| 退出码 | 含义 | 动作 |
|---|---|---|
| `0` | 成功，或已给出明确引导 | 继续下一步 |
| `1` | 执行失败 | 停下报告，不要重试写操作 |
| `2` | 需要人工确认或权限不足 | 问用户，拿到答复再动 |
| `3` | 输入数据不合规 | 回上一步重新取数 |
| `130` | 用户中断 | 先读台账确认写到哪了 |

## 错误码

### 认证类

| 错误码 | 处理 |
|---|---|
| `AUTH_EXPIRED` | 内网 Auth 失效。告诉用户重新完成内网认证，**停止本轮**。不要重试绕过，不要改用浏览器自动化代操作。 |
| `AUTH_FAILED` | 当前账号没有该看板 / 接口权限。停止并告知用户申请权限，不要借用他人凭据。 |

这两个不解决，后面每轮都是空转，所以必须暂停循环而不是静默跳过。

### 取数类

| 错误码 | 处理 |
|---|---|
| `EMPTY_WINDOW` | 窗口内没有任何账户数据。大概率实时数据未回补，等下一轮。**禁止拿空结果继续走写入流程。** |
| `TEMPLATE_MISSING` | `references/olap_query_template.json` 丢了。这份模板必须整份原样提交给 OLAP——裁掉隐藏配置会触发 `指标维度组合不支持查询`，所以不能手拼一个简化版替代。 |
| `DUPLICATE_ACCOUNT` | 输入 CSV 里同一账户多行。回取数环节按账户ID聚合。**不要手工删行，也不要对 ROI 取算术平均**——ROI 是比值，正确口径是消耗加权（等价于总变现÷总消耗）。 |

关于 `DUPLICATE_ACCOUNT` 为什么不能取平均：同一账户 `7800 元 @ 0.89` 和
`2400 元 @ 0.71` 两段量，加权结果 `0.8476`（落观察区，不操作），简单平均
`0.80`（会压价 -0.01）。结论完全相反。

### 决策类

| 错误码 | 处理 |
|---|---|
| `TEST_FAILED` | 决策表测试红了。禁止在这个状态下跑生产。先定位是 decide.py 改错了还是测试预期该更新。 |

### 写入类

| 错误码 | 处理 |
|---|---|
| `API_ERROR` | 上游返回业务错误。原样记录报错文案，跳过该账户继续下一个，最后在报告「未执行」里列出。**写请求不自动重试**，避免同一账户建出两条策略。 |

常见的具体报错：

| 平台报错 | 原因与修法 |
|---|---|
| `size must be between 0 and 32` | 策略名或 `background` 超 32 字符（中文按字符计）。命名固定为 `短剧-自动-{账户ID}`，background 只写简短说明。 |
| 策略名已存在 | 命名漏了账户ID。同一轮多个账户算出同一新系数是常态，必须带账户ID。 |
| 已有基数，不得重复新建 | 复用了上一轮的基数文件。每轮都要重新查基数——上一轮新建过基数的账户这一轮已经有了。 |

### 参数与文件类

| 错误码 | 处理 |
|---|---|
| `INVALID_ARGUMENT` | 参数不合法。核对后重跑，不要猜测补默认值。 |
| `INPUT_NOT_FOUND` | 输入文件不存在。确认上一步真的落盘成功了，不要跳过取数直接决策。 |
| `UNEXPECTED_ERROR` | 未预期异常。读 stderr 的诊断行定位。不要盲目重试写操作。 |
| `INTERRUPTED` | 用户中断。先读台账确认哪些账户已成功写入，再决定是否续跑——台账是唯一依据，不要靠聊天记录回忆。 |

## 不属于错误但容易误判的情况

| 现象 | 说明 |
|---|---|
| 某轮几乎全是 `SKIP_COOLDOWN` | 正常。窗口 30 分钟、触发 20 分钟，稳定期约每 2 轮有 1 轮真正下手。 |
| OLAP 返回 `result=1` 且 `error_msg=canDiff` | 正常返回（同期对比提示），有列有行就能用。真正的失败是拿不到任何列或行。 |
| 大量账户 `base_source=PLATFORM_LATEST` | 生产常态：账户被多条生效策略覆盖，脚本已按创建时间取最新那条作基数，不需要逐个确认。 |
