# 样例与边界速查

## 边界速查

这些值覆盖了全部七档和异常情况，对不上就说明理解错了区间：

| ROI | 命中区间 | 动作 | 增量 |
|---|---|---|---|
| `1.12` | `roi > 1.00` | 顶价 | `+0.03` |
| `1.00` | `0.90 < roi <= 1.00` | 顶价 | `+0.02` |
| `0.97` | `0.90 < roi <= 1.00` | 顶价 | `+0.02` |
| `0.90` | `0.85 < roi <= 0.90` | 顶价 | `+0.01` |
| `0.8501` | `0.85 < roi <= 0.90` | 顶价 | `+0.01` |
| `0.85` | `0.84 < roi <= 0.85` | **不操作** | `0.00` |
| `0.845` | `0.84 < roi <= 0.85` | **不操作** | `0.00` |
| `0.84` | `0.80 <= roi <= 0.84` | 压价 | `-0.01` |
| `0.80` | `0.80 <= roi <= 0.84` | 压价 | `-0.01` |
| `0.78` | `0.75 <= roi < 0.80` | 压价 | `-0.02` |
| `0.75` | `0.75 <= roi < 0.80` | 压价 | `-0.02` |
| `0.7312` | `roi < 0.75` | 压价 | `-0.10` |

四个容易踩的点：

- `(0.84, 0.85]` 是**观察区**，不写任何策略。顶价要求严格大于 `0.85`，压价最高档只到 `0.84`，这段业务规则没覆盖，所以保持原系数。
- `0.85` 在观察区里，`0.8501` 才是顶价，`0.84` 才是压价。三个值挨着但动作完全不同。
- `0.90` 是 `+0.01`，`1.00` 是 `+0.02`：区间右端归上一档。
- 最低档是 `-0.10`，不是 `-0.03`，不要顺着上面三档的步长推。

## 改阈值的流程

业务确认要调整区间时：

1. 先改 `scripts/test_decide.py` 的期望值（包含边界点）。
2. 再改 `scripts/decide.py` 的 `_BANDS`。表里每行是 `(区间文案, 比较方式, 阈值, 增量, 动作)`，顶价档用 `gt`（严格大于），压价档用 `ge`（大于等于），最后一档 `always` 兜底。
3. 同步更新 `SKILL.md` 的决策表和本文件的边界速查。
4. 跑通测试：

```bash
uv run scripts/test_decide.py
```

四处必须完全一致，否则文档和代码会各说一套，这是这类脚本最常见的事故来源。

另外注意：改动上下两档的阈值时，检查一下有没有像 `(0.84, 0.85]` 这样谁都不管的区间。`test_no_gap_across_grid` 只保证不抛异常，保证不了这段区间的动作符合业务预期。
