# OLAP 接口与模板

## 端点

```
POST https://internal.example.corp/api/v1/data/query
```

请求头必须带：

```
Kwaibi-View-Query-Type: 8
kwaibi-request-module: olap
Referer: <看板页面地址>
```

鉴权走 `SmartSSOSession`，不要自己读 cookie 文件或硬编码 token。

**注意端点容易搞错**：`bi-platform.example.corp/api/v1/data/query` 是另一个接口，字段协议不同、filter 会被静默忽略。抓包时确认域名是 `olap`。

## 怎么拿到模板

模板就是网页上那次查询的真实请求体。不要手写，也不要凭字段名猜——猜出来的 filter 会被接口静默忽略，返回的数据看起来正常但过滤条件根本没生效。

正确做法：

1. 用 `agent-browser` 打开目标看板页面，把维度、指标、筛选条件都调成你要的样子
2. 抓 `POST /api/v1/data/query` 的完整请求体
3. 原样存成 JSON 文件，放进 `references/`
4. 在配置里指向它

抓包细节看 `agent-browser` skill。

## 模板里的日期 filter 必须由框架重写

这是最容易踩的坑，也是唯一会**静默出错**的地方。

模板里的 `filters[].filterValue.startTime/endTime` 写死了你抓包那天的日期：

```json
{
  "filters": [
    {
      "filterValue": {
        "startTime": 1789401600000,
        "endTime": 1789487999999
      }
    }
  ]
}
```

不重写会怎样：**从次日零点开始，取的一直是抓包那天的数据。** 而接口照样返回 200、数据完整、格式正确、行数正常——你从响应里完全看不出问题。

这个坑真实发生过：一个每 15 分钟跑一轮的调价流程，跨天后连续拿昨天的指标去改今天的出价，跑了整个上午才被发现。

`fetch.py` 每次都按取数窗口重写这两个字段，**模板里找不到该字段时直接抛错**而不是静默继续。所以：

- 不要手改模板里的日期，改了也会被覆盖
- 不要删掉模板里的日期 filter，删了脚本会报错

## 响应结构

```json
{
  "data": {
    "columns": [{"name": "账户ID"}, {"name": "__time"}, ...],
    "dataList": [
      ["119632691", {"v": "2026-09-15 23:55", "r": 1789487700000},
       {"v": "395.13元", "r": 395.132}, {"v": "0.85", "r": 0.8474307320085447}]
    ]
  },
  "result": 1,
  "error_msg": "canDiff"
}
```

### 单元格取 `r` 不取 `v`

`{"v": "395.13元", "r": 395.132}`：

- `v` 是展示值——带单位（`元`、`%`）、被四舍五入过
- `r` 是原始值

拿 `v` 去算要么因为后缀直接崩，要么精度被污染。上例 `v` 显示 `0.85`，`r` 实际是 `0.8474307320085447`——如果观察区是 `[0.84, 0.85)`，用 `v` 会判成「要动」，用 `r` 才知道该「不动」。

### `result: 1` + `error_msg: "canDiff"` 是正常的

那是同期对比提示，不是错误。有 `columns` 和 `dataList` 就能用。真正的失败是拿不到任何列或行。

### `__time` 是分钟粒度

数据集返回分钟明细，`v` 形如 `2026-09-15 23:55`。一个 15 分钟窗口典型命中 3 个自然分钟点，30 分钟窗口命中 6 个。

**窗口越短命中的分钟点越少，小额对象的指标抖动越大**，可能出现「这轮压、下轮顶」的来回拉扯。遇到这种模式先报告，不要自己加平滑。

### 会有「汇总」行

响应里可能混入 `__time` 为 `汇总`、主键为 `合计` 的行。`numeric_key_only` 默认为 `true` 会把它们筛成 `SKIP_NOT_TARGET`。

## 分页的坑

这个接口的 `offset` 参数**会被静默忽略**——翻第 2 页拿到的还是第 1 页。所以不要指望分页拉更多数据，只能靠调 `limit`。

`limit` 也不是想设多大就多大：某些维度指标组合下设太大会返回「指标维度组合不支持查询」。抓包时页面上用的值通常是安全的，照抄就行。

## 常见报错

| 报错 | 原因 |
|---|---|
| `指标维度组合不支持查询` | `limit` 太大或维度指标组合非法。回到抓包时的值 |
| 401 / 302 | SSO 失效，重新认证 |
| 403 | 账号没有该看板权限 |
| 返回空 `dataList` | 窗口内确实没数据，或日期 filter 指向了错误日期 |
| 列名对不上 | 看板字段被改过，重新抓模板并更新配置的 `columns` |
