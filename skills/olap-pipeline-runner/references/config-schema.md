# 配置文件规范

一份 JSON 定完整业务。框架不含任何硬编码字段名或阈值——这个文件说明每个字段怎么填。

## 顶层结构

```json
{
  "name": "my-pipeline",
  "fetch":    { ... },
  "enrich":   { ... },
  "evaluate": { ... },
  "write":    { ... }
}
```

四段各自独立读自己那一节。只跑取数就只需要填 `fetch`。

## fetch — 取数与聚合

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `template` | ✅ | — | OLAP 请求体模板路径，相对配置文件所在目录 |
| `columns.key` | ✅ | — | 主键列名（如 `账户ID`） |
| `columns.time` | ✅ | — | 时间列名（通常是 `__time`） |
| `columns.metric` | ✅ | — | 指标列名 |
| `columns.weight` | 条件 | — | 权重列名。`aggregation=weighted_mean` 时必填 |
| `aggregation` | | `weighted_mean` | `weighted_mean` / `sum` / `mean` |
| `window_minutes` | | `15` | 取数窗口长度 |
| `lag_minutes` | | `5` | 右端留白，规避实时数据回补延迟 |
| `referer` | | adsdata 首页 | 请求头 Referer，某些看板会校验 |

### 窗口语义

窗口是 `[now - lag - window, now - lag)`。例：`window_minutes=15, lag_minutes=5`，12:36 触发 → 取 `12:16 ~ 12:31`。

右端留白不能省。实时数据集有回补延迟，贴着 `now` 取会拿到半成品数据——分钟行已存在但指标还没算完，值偏低。

### 聚合口径怎么选

`weighted_mean` 是 `Σ(权重×指标) ÷ Σ权重`，等价于「总量比总量」。

**这跟算术平均能给出相反结论**，看例子：

| 分钟 | 权重（消耗） | 指标（ROI） |
|---|---:|---:|
| 12:20 | 7800 | 0.89 |
| 12:25 | 2400 | 0.71 |

- 加权：`(7800×0.89 + 2400×0.71) ÷ 10200 = 0.8476`
- 算术：`(0.89 + 0.71) ÷ 2 = 0.80`

如果 `[0.84, 0.85)` 是观察区，加权说「不动」，算术说「要动」。**选错不会报错，只会静默算错。**

比率类指标（ROI、点击率、成本率）几乎总该用 `weighted_mean`。绝对量（消耗、曝光数）用 `sum`。

## enrich — 拉平台现值

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `id_field` | | `accountIds` | 策略条目里存名单的字段名 |
| `value_field` | | `bonusRate` | 策略条目里存当前值的字段名 |
| `multi_hit_policy` | | `latest` | 多命中时怎么办，见下 |
| `default_value` | | — | 查不到现值时的兜底基数。不配则该对象跳过 |

### multi_hit_policy

一个主键被多条生效策略同时覆盖是常态（实测 139 个对象里 51 个如此）。

| 值 | 行为 | 什么时候用 |
|---|---|---|
| `latest` | 按 `createTime` → `updateTime` → 策略 ID 取最新那条 | 常驻循环。最后下发的策略代表当前生效意图 |
| `ask` | 标 `MULTIPLE_EFFECTIVE`、`needs_user_choice=true`，等人工选 | 单次操作、值差异大且后果重 |
| `fail` | 直接抛错中止 | 不允许歧义的场景 |

选 `latest` 时 `chosen_strategy_id` 记录了用的是哪条。**报告里必须带上**——出问题时这是唯一的回溯线索。

`ask` 会在常驻循环里卡死（51 个冲突要问 51 次），所以循环场景别用。

## evaluate — 决策档位

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `bands` | ✅ | — | 档位表，见下 |
| `guardrail.min` / `.max` | | — | 新值护栏。超出标 `HOLD_NEEDS_CONFIRM`，不写入 |
| `cooldown_minutes` | | `0` | 冷却期。见下 |
| `decimals` | | `2` | 新值保留小数位 |
| `numeric_key_only` | | `true` | 非纯数字主键（汇总行等）直接跳过 |

### bands 区间语义

**左闭右开 `[min, max)`。** `min` 省略表示负无穷，`max` 省略表示正无穷。

```json
"bands": [
  {"max": 0.75, "delta": -0.10},
  {"min": 0.75, "max": 0.80, "delta": -0.02},
  {"min": 0.80, "max": 0.84, "delta": -0.01},
  {"min": 0.84, "max": 0.85, "delta": 0},
  {"min": 0.85, "max": 1.00, "delta": 0.01},
  {"min": 1.00, "delta": 0.03}
]
```

脚本启动就校验重叠和空隙，两者都直接报错：

- **重叠**：相邻档位 `max` 大于下一档 `min`，同一个值命中两档，结果取决于顺序——不确定性不能上生产。
- **空隙**：相邻档位之间有断层，落进去的值无档位可用。**不校验的话会静默变成「不动」，跟观察区一模一样，你根本发现不了规则漏了一块。**

所以相邻档位的 `max` 和下一档的 `min` 要写相等。

### `delta: 0` 和「没配档位」不是一回事

| 情况 | 状态 | 含义 |
|---|---|---|
| `delta: 0` | `NO_ACTION` | 有意不动（观察区），规则完整 |
| 落不进任何档位 | `SKIP_NO_BAND` + 整体报错 | 规则有洞，必须补 |

别用「不配档位」来表达「不动」。

### cooldown_minutes

**只在窗口长度大于触发间隔时才需要开。**

| 关系 | 重叠 | 冷却期 |
|---|---|---|
| 窗口 15min，触发 15min | 零重叠 | `0`（不需要） |
| 窗口 30min，触发 15min | 50% | 设成 `30`（等于窗口长度） |

它防的是「同一批数据被重复消费」：两轮窗口重叠时同一批数据被读到两次，不加约束就会对同一对象连续下手两次，`-0.10` 变成 `-0.20`。

锚定**窗口长度**而非触发间隔，因为重复消费的根源是窗口重叠。

冷却期在档位判定**之后**才判——观察区本来就不动，不该被报成「冷却中」，否则你会误以为它被拦了。

## write — 写入

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `name_template` | ✅ | — | 策略命名模板 |
| `name_max_length` | | `32` | 名称长度上限，中文按字符计 |
| `end_time` | | `end_of_day` | 失效时间：`end_of_day` / `+Nd` / `+Nh` / 毫秒时间戳 |
| `background` | | 空 | 策略备注，同样受长度限制 |
| `fields.*` | | 见下 | 请求体字段名映射 |
| `constants` | | — | 固定塞进请求体的常量字段 |

### fields 映射

不同策略类型字段名不同，所以走配置：

| 角色 | 默认字段名 |
|---|---|
| `name` | `name` |
| `background` | `background` |
| `value` | `bonusRate` |
| `id_list` | `accountIds` |
| `begin_time` | `beginTime` |
| `end_time` | `endTime` |

### 命名长度

平台对策略名有硬限制，超了返回 `size must be between 0 and N`。**中文按字符计**，`IAA首日ROI_114368154_顶价_0.70_202609151251` 是 39 字符会被拒。

脚本在发请求前就检查，不等平台报错。

### end_time 为什么默认当天

自动调整是当日级干预，过了今天就该失效重新评估。设跨天生效意味着某天的临时判断会一直生效下去，而那天的数据早就不成立了。
